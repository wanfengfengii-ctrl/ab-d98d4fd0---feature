# 主帆修补 · 帆布联合排版工作台

历史帆船修补主帆前，帆装师在浏览器工作台录入 **2–3 张可用帆布、3–5 块破损补片、每块补片 2–4 个
经批准的整数坐标裁切候选**。系统在本机联合为每块补片选择恰一个候选，避免「局部挑了最省料的位置，
却让其他补片无处可裁」。

## 选优规则（严格按顺序比较）

1. **使用帆布张数最少**；
2. 张数相同，**各已用帆布剩余面积的最大值最小**（把占用摊匀，避免一张被吃空）；
3. 再相同，**按补片录入顺序展开的候选序号（1 起）字典序最小**。

候选可采用的三个必要条件：

- **纤维方向相符**：补片纤维与帆布经线方向一致（旋转 90° 后两向对调）；
- **完整落在可裁区域内**：裁片不得侵入帆布四边等宽的边缘禁裁带；
- **不与同布其他采用裁片正面积重叠**：边贴边允许，像素级正面积交叠禁止。

无解时按补片录入顺序指出**首块不存在任何可兼容候选**的补片；若每块单看可兼容、但联合落位时
互相冲突，则给出候选对冲突清单。草稿任何修改都会使旧结论失效（版本号 +1，结论区显示失效横幅）。

## 运行（Docker Compose）

```bash
# 常驻 Web（默认宿主机 8080，端口可通过 WEB_PORT 配置）
docker compose up web --build
WEB_PORT=9090 docker compose up web        # 改用宿主机 9090

# 一次性校验服务：代码测试 + 前端构建 + 候选冲突业务冒烟
# 跑完自行退出，退出码 0 全部通过、非 0 有失败
docker compose run --rm verify
```

- Web 健康检查：`GET /healthz`（Docker `HEALTHCHECK` 与 compose healthcheck 均已配置）。
- 宿主机端口：`.env` 中 `WEB_PORT`（见 `.env.example`）或环境变量临时覆盖。
- `verify` 属于 `verify` profile，不会随 `web` 常驻启动。

## 本地开发（Node ≥ 22）

```bash
npm ci
npm test          # 领域单元测试（node --test）
npm run build     # esbuild 打包前端到 dist/
npm run verify    # 测试 + 构建 + 业务冒烟，退出码报告
npm start         # Web 服务（PORT 环境变量可改端口）
```

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/healthz` | 健康检查 |
| GET | `/api/draft` | 当前草稿、版本号与已生成结论 |
| PUT | `/api/draft` | 保存草稿（校验失败返回 400；版本推进，旧结论失效） |
| POST | `/api/plan` | 对当前草稿执行联合排版 |
| POST | `/api/reset` | 恢复内置示例草稿 |

## 目录

```
src/core/validation.js   录入校验（数量/整数/方向/禁裁边）与矩形几何
src/core/planner.js      联合求解（回溯 + 三级目标）与候选排除理由
src/server/              Express 服务、一次性 verify 编排、业务冒烟
web/                     浏览器工作台（录入、SVG 帆布示意、采用/排除明细）
scripts/build.js         esbuild 构建
test/planner.test.js     领域单测
Dockerfile, docker-compose.yml, .dockerignore
```

## 内置示例的设计意图

- 帆布甲为经纱、帆布乙为纬纱；方肘补（经纱）只能落甲布，其全部甲布候选都与大肘补的
  「甲布角落」候选正面积重叠——**局部贪心选该候选会令方肘补无处可裁**；
- 联合求解把大肘补改放到乙布（顺时针 90° 旋转），小角补则为摊匀剩余面积放到甲布，
  最优候选序号为 `[2, 1, 4]`。
